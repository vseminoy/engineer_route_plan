# Интеллектуальный сервис планирования маршрутов выездных инженеров

Прототип для хакатона «Билайн Бизнес» — автоматическое распределение заявок между выездными бригадами, построение маршрутов и перепланирование при внештатных событиях.

Полный комплект технической документации (бизнес-требования, ТЗ, спецификации бэкенда/фронтенда, словарь данных, алгоритм) — [`docs/bft/`](docs/bft/00_index.md).

## Допущения

### Норматив выполнения аварийной заявки (100 минут)

Источник: [`docs/Нормативы.xlsx`](docs/Нормативы.xlsx), уточнён условием **conditions.md №45**:

> «Дорога входит в норматив выполнения нормативной аварийной заявки. На дорогу до ТКД выделяется 20 минут (т.е. 80 минут на точке)».

Из этого следуют два разных, не взаимозаменяемых понятия времени для аварийной заявки:

1. **`duration_min` (поле модели, время на объекте) = 80 минут** — только «Технические работы» по нормативу, без «Документов» (в нормативе для аварии документы = 0 мин). Это значение закладывается в расписание бригады при построении маршрута.
2. **100-минутный норматив (BR-14, контроль SLA)** — это **фиксированная** сумма 20 (норматив на дорогу до ТКД) + 80 (на объекте), отсчитываемая с момента фактического поступления аварийной заявки. 20-минутная составляющая — это плановый норматив, **а не результат расчёта реального времени в пути через OSRM**.

Важно не путать эти два понятия с построением самого маршрута:

- Фактический маршрут бригады до места аварии и её реальный пробег/время в пути **по-прежнему считаются через OSRM по дорожной сети** (BR-10) и участвуют в обязательных метриках плана (число задействованных бригад, суммарный пробег).
- 20-минутный норматив используется **только** для контроля соблюдения 100-минутного SLA (BR-14) — как ожидаемое/бюджетное время в пути, а не как замена реального расчёта маршрута. Реальное время в пути OSRM до конкретной аварии может отличаться от 20 минут в обе стороны.

Для остальных типов заявок (Подключение, Дозаказ, Локальная заявка) это правило **не действует** — условие №45 говорит только про аварийную заявку. Для них компонент «Дорога до клиента» в `Нормативы.xlsx` остаётся справочным ориентиром и **не** используется в расчётах: `duration_min` = «Технические работы» + «Документы» (время на объекте), а время в пути между точками маршрута всегда считается отдельно через OSRM и добавляется к нему при построении расписания. Это по-прежнему допущение команды, а не требование организатора.

Подробности и таблицы с разбивкой по типам заявок — [`docs/bft/07_data_dictionary.md` §5](docs/bft/07_data_dictionary.md#5-нормативы-длительности-работ-docsнормативыxlsx-минуты) и [`docs/bft/05_spec_backend.md` §8](docs/bft/05_spec_backend.md#8-модуль-расчёта-нормативов-длительности).
